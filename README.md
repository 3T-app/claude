# 商圏うんちく（試作版・東京）

テーマは **「商圏をうんちくに」**。東京の街を「商圏」という見かたで学び、デートや友人との会話のネタ（会話デッキ）にできるアプリです。飲食店向けの立地診断もできます。

## 画面構成（下のタブ）

| タブ | できること |
|---|---|
| 📍 立地調査 | 店名・住所・業態を入れて「決定」を押すと、AIが **集客基盤／客層の多様性／消費サイクル／競合性／接続性** を1〜5の5段階で評価。分析レポート、バズりそうなメニュー案、その業態で今はやっているもの（SNSトレンド巡回）を表示。診断結果について **🤖 AIに質問する（1回100円）** |
| 🗺️ 商圏を学ぼう（中央） | 東京の街47か所を地図と一覧から選ぶか、自由入力で検索。街全体の商圏の講義（ゾーン、時間帯ごとの主役、客層、接続性、歩き方）と、そのまま使える **うんちくカード** を表示。**🤖 AIに質問する（1回100円）** |
| 💬 みんなの投稿 | 街歩きで気づいた商圏を写真つきで投稿。LINEのオープンチャットのように自分の投稿は右、みんなの投稿は左に並ぶ。他人の投稿には **リアクションだけ** つけられる（返信なし） |

運営用の **/admin** では、AIに「どこを見てほしいか」を文章で教えられます。

## 商圏の分析手順（講義・立地調査）

池袋の分析をお手本に、東京のどの街でも次の順で分析します（手順とお手本は `data/teachings.md`）。

1. 町を支える人とニーズ（e-Stat の統計＋ニュース）
2. 地図の店から商圏を読む（OpenStreetMap の店・施設の位置＋ホットペッパー）
3. 町の歴史と、今に残る名残（Web・ニュースの調査）
4. 新しい勢力と今の魅力
5. 店と店の関係：補完（はしご・呼び込み）、集積、価格競争
6. 商圏の割れ方：アニメ商圏・電気街商圏・夜の繁華街などに分け、地理院の地図に色分けして表示
7. 昼と夜
8. まとめ（その街をひとことで言うと）

この手順は「考える順番」で、講義の見出しにはしません。街ごとに **切り口**（地形、駅の東西の逆転、跡地の使い方、来る人と住む人など）を一つ決め、その切り口に沿った3〜4章の読み物として書きます。見出しとまとめの言い回しも街ごとに変えます（書き方は `data/teachings.md` の「講義の書き方」）。項目別の詳しい分析は「🔍 もっと詳しく」にまとめ、その街の主役の項目を先頭で開いて表示します。

立地調査では、店がどの商圏の中・端・外にあるかと、周りの実在の店との補完・集積・価格競争を判定し、それを5つの評価軸の根拠にします。

- **全48エリアの分析を保存済み**（`data/analyses/<id>.json`）。Claude Code が Web とニュースを調べて書いたもので、APIキーがなくても講義として表示されます。キーがあるときは、これを土台に地図の店データで分析し直し、次に開いたときから表示します
- 分析をやり直すときは Claude Code で `/analyze-areas`（街を絞るなら `/analyze-areas shibuya ginza`）、確認は `npm run check:analyses`
- 街ごとの **運営の現地調査メモ** を `/admin` で書けます（池袋は `data/area-notes/ikebukuro.md` が初期値）。AIは最も信頼できる事実として使います
- 店・施設の位置は OpenStreetMap（Overpass API、キー不要）から取得し、画面に出典を表示しています
- 講義は初回に統計・地図の店・Web調査を行うため2〜3分かかります。作り直している間は前の講義を表示します

## 商圏そのものを学ぶ（/learn/basics）

「商圏を学ぼう」の一番上の入口から開く、商圏の基本を学ぶページ。

- **📇 用語・概念カード**：商圏、集積、補完（はしご・呼び込み）、価格競争、回遊、動線、昼夜間人口比、門前町、闇市と横丁、跡地の再開発、インバウンド、持続可能な観光、5つの評価軸など22枚。タップすると説明と「この現象が見られる街」が出て、その街の講義へ飛べる（`src/lib/glossary.ts`）
- **🧠 商圏を考える**：全48エリアの分析から、街・商圏・業態をランダムに選んだ出店問題を出す。答えを書くとAIが「よいところ・まだ考えられること・次の問い・考え方の一例・関係する用語」でコメントする（`/api/exercise`）。APIキーがあるときは1人1日10回まで無料（`EXERCISE_PER_DAY`）。デモ表示では、答えに入っている見かた（客層・人の流れ・店と店の関係・時間帯）からコメントする

## 飲み屋街・昼の街・会話デッキ（商圏を学ぼう）

- 飲み屋街は18歳以上の方向け。開く前に「18歳以上ですか？」と確かめ、「はい」のときだけ表示する（答えはその端末に保存）

- **🍺 飲み屋街**（「もっと詳しく」の中）：開くと上の地図が飲み屋街の分布に切り替わる。①駅の出口をすべて見つける → ②出口から先の人の流れ → ③飲み屋街の商圏（雰囲気・客層・予算感・にぎわう時間・流れてくる出口・大人の楽しみ方・注意）の順に表示する
  - 全48エリアの事前分析（`data/analyses/<id>.json` の `nightlife`）をすぐ出し、出口の位置は OpenStreetMap の駅の出入口で確かめる（見つからないときは方角からのおおよその位置）
  - APIキーがあると、OpenStreetMap の出口と飲み屋の位置、Web の調査からAIが分析し直し、7日間保存する（`/api/nightlife`）
  - 飲み屋街ごとの「🔎 この飲み屋街でお店を探す」で、確認（外部のサイトに移動します。よろしいですか？）のあと Google マップの検索が開く。OK のときだけ回数を記録し、`/admin` と `npm run report:clicks` で日ごとの回数・1日平均・前の4週間からの増減・増減した飲み屋街と、その街の最近のニュースを見られる（APIキーがあれば `/admin` でAIが増減の理由を分析）。記録は回数と、重複を数えるための短いハッシュだけ
- **🏗️ 土地と再開発**（「もっと詳しく」の中）：駅のまわりの土地を誰が持っているか（鉄道会社・デベロッパー・寺社・行政・多くの地権者）と、それが商圏の変わる速さと大きさにどう効くか。「池袋と比べると」のように比べる街へのリンクつき。自治体の都市計画やニュースで確かめた18エリアに入っている（`data/analyses/<id>.json` の `land`）。APIキーがあるとAIの講義でも書き、確かめられなければ出さない
- **☀️ 昼の街**（「もっと詳しく」の中）：朝・ランチ・午後・休日の昼に、誰がどこに何をしに来るか
- **💬 会話デッキ**：地図のすぐ下。「池袋に釣具屋が多いのはなんで？」のように、その街のイメージと違う店・ものが成り立つ理由を商圏で答える問いのカード。タップすると答えが出る

## 毎日育つ「商圏を学ぼう」

- **🆕 この街のアップデート**：毎朝のニュース巡回（`/crawl-news`）が、その日に見つけた街の変化を、日付つきで事前分析（`data/analyses/<id>.json` の `updates`）に書き足します。大きな変化は本文の章や「新しい勢力」も直します
- **AIによる作り直し**（APIキーがあるとき）：講義を開いたとき、材料（投稿とリアクション、運営の調査メモ、街のニュース、事前分析の更新）が前回から変わっていれば、1日1回まで裏で作り直します。AIは前回の講義と比べて「何が新しく分かったか」を書き、アップデートに積み上げます。材料が同じでも7日たてば作り直します
- **📅 今日のピックアップ**：講義の中の名残・店と店の関係・商圏・通りの違いなどから、毎日ちがう話を1つ取り出して表示します（同じ日でも街ごとに違うものが出ます）

## AIに質問する（1回100円）

「商圏を学ぼう」（講義の上のボタン、本文の終わり、ページ下の質問欄）と「立地調査」（総合点の下のボタン、レポート下の質問欄）から、AIに質問できます。質問は **1回ごとに100円** です。

1. 質問を書いて「100円で質問する」→ 確認画面で「100円を払って質問する」
2. Stripe のカード決済の画面へ移動し、支払うと元の画面に戻る
3. サーバーが Stripe で支払い（金額・通貨・質問ID）を確かめてから、AIが回答する。回答は保存され、同じ街・同じ調査結果で続けて質問すると前の質問と回答もふまえて答える

- 決済は Stripe Checkout（`STRIPE_SECRET_KEY`）。SDKは使わず REST で呼んでいます
- `STRIPE_SECRET_KEY` が未設定だと **テスト決済**（実際には請求せずに回答）で動き、画面にその旨を表示します。公開する前に必ず設定してください
- 回答の作成に失敗しても支払いは残り、追加料金なしで「回答を作り直す」ことができます
- 支払いをやめて戻ると、質問は入力欄に戻ります。支払われずに1日たった質問は消えます
- 立地調査の結果は `data/db.json` に保存し（最新300件）、支払いのあと `/diagnose?d=<id>` で表示し直します
- 日本で有料のサービスを公開するときは、特定商取引法に基づく表記（販売者名・連絡先・返金の条件など）が必要です

## 立地調査の集客基盤（駅の出口から集計）

- 飲み屋街の分析と同じく、店の住所（国土地理院の住所検索）のまわり800m以内の駅の出口をすべて OpenStreetMap から読み取り、一番近い出口までの距離と徒歩の分数（直線距離×1.25÷分速80m）で目安を出す：2分以内5・4分4・6分3・9分2・それ以上1。800m以内に駅が3つ以上か、500m以内に出口が10か所以上なら+1
- 出口が飲み屋街の分析（`nightlife.exits`）にある出口と同じなら、その出口から先の人の流れも表示する。OpenStreetMap が使えないときは、分析の出口（方角からのおおよその位置）で測る
- AIの集客基盤の点数は、この目安から±1点までにそろえる（デモ表示では目安をそのまま使う）。結果の画面に「🚉 集客基盤の集計（駅の出口から）」として、出口ごとの距離と徒歩の分数を出す

## みんなの投稿（全国どこでも）

- 東京の48の街に加えて、「上の街以外（全国どこでも）」を選ぶと、都道府県と駅名・地名で投稿できる。位置は国土地理院の住所検索で調べ、東京の48の街から1.5km以内ならその街の投稿としても扱う
- 一覧は「すべて」「東京の街」「東京の48の街以外（全国）」「都道府県」で絞り込める
- AIは投稿から、5つの評価軸に加えて、店と店の関係（はしご・呼び込み・集積・価格競争）と、組み合わさっている店の種類（例：パスタ店×ジェラート店）を読み取る。人が「気づいた」組み合わせは補完関係が強い証拠として扱う
- 立地調査では、店から2km以内の投稿（全国どこでも）と、その業態がかかわる補完の組み合わせ（全国）を「👥 みんなの投稿で見つかった組み合わせ」として示し、評価と提案に使う
- `/admin` の「全国のみんなの投稿の分析」と `npm run report:posts` で、都道府県ごとの投稿・関係・組み合わせ・よく反応された気づきを見られる（APIキーがあればAIが地域ごとの読みと、全国版に向けて次に集める投稿を提案）

## AIの「育成」のしくみ

モデル自体を再学習するのではなく、毎回のプロンプトに次の2つを差し込んで、使うほど街の実態に寄っていくようにしています。

1. **運営からの教え**（`data/teachings.md` が初期値。/admin で編集）— 5つの評価軸の定義や、アプリの思想
2. **投稿から読み取った気づき** — 投稿時にAIが写真とコメントを読み、「どの評価軸の話か」「なぜその組み合わせが客を呼ぶのか」を抽出して保存。リアクションが多い投稿ほど重く扱う

気づきは、その街の講義・チャット、周辺の立地調査、そして他の街の立地調査の「接続性」の参考事例として使われます。投稿が増えると街の講義は自動で作り直されます。

## AIが自動で使う外部データ（無料・審査なし）

APIキーを `.env.local` に入れると、講義と立地調査のたびに自動で使います。入れなければ使わずに動きます。`/admin` の「接続テスト」でつながるか確認できます。

| データ | 使いみち | キャッシュ |
|---|---|---|
| **YouTube Data API**（`YOUTUBE_API_KEY`） | 業態ごとに直近30日で再生の多い動画を、流行のシグナルとして使う。あわせて韓国・台湾・アメリカで、その国の言葉で検索した流行動画を「海外の先取り」として使う | 日本24時間・海外3日 |
| **ホットペッパーグルメ**（`HOTPEPPER_API_KEY`） | 店の周り300m・1kmの同業の数、500m以内のジャンル構成（競合性・接続性）。講義では街の店の構成 | 7日 |
| **e-Stat**（`ESTAT_APP_ID`） | 区市の一人暮らしの割合・65歳以上の割合・昼夜間人口比（客層の多様性・消費サイクル） | 30日 |

- ホットペッパーのデータを表示する画面には、規約に沿ってクレジットを出しています
- e-Stat は既定で「社会・人口統計体系 市区町村データ」（`0000020201`）を使い、項目は名前で探します。表を変えるときは `ESTAT_STATS_DATA_ID` を設定してください

## X・Instagram の流行（毎日の手入力）

X・Instagram は公式APIが有料または審査制なので、運営が毎日 `/admin` の「今日の流行メモ」に入れる運用です。スマホからも入力できます。直近14日のメモが、立地調査の「今はやっているもの」とバズるメニュー案で最優先に使われます（業態を「全般」にするとすべての業態で使われます）。

## 毎日のニュース巡回（`/crawl-news`）

Claude Code が毎朝、Web検索で元の記事（新聞社・Webメディア・自治体・プレスリリース）を探し、次の2つを `data/news/` に保存します。

- **街の変化**（`data/news/areas/<id>.json`）：48エリアの開業・閉店・再開発・イベント。48エリアを6日で1周（`npm run news:targets` で今日の対象を確認）し、東京全体の検索で見つけたものも追加
- **話題の食べ物・お店**（`data/news/buzz.json`）：業態ごとの、いまニュースで話題の商品・お店

- **海外トレンド**（`data/news/global.json`）：海外で流行している食べ物・店、日本に上陸したもの、訪日客が東京で探しているもの。毎日ちがう国・都市を3つ以上見る。立地調査の「今はやっているもの」と、バズるメニュー案の先取りの材料に使う

講義には「📰 最近の街のニュース」として表示され、AIの分析（講義・立地調査の競合性と接続性・バズるメニュー）にも使われます。大きなニュースは街の事前分析にも反映します。確認は `npm run check:news`。

Yahoo!ニュースのRSSは公式の利用条件で個人利用に限られ、アプリでの利用が許可されていないため使いません。LINE NEWS も公開の取得手段がないため使いません。

## Web記事の巡回

立地調査では、Web記事の巡回結果も次の順で使います（3日以内の新しいもの）。

1. **Claude Code での巡回**：このリポジトリで Claude Code を開き `/crawl-trends`（業態を絞るなら `/crawl-trends cafe`）を実行すると、X・Instagram・TikTokで話題のトレンドをWebで調べて `data/trends/<業態>.json` に保存します
2. 1が無ければ、診断時にアプリがClaude APIのWeb検索で調べて24時間キャッシュ

X・Instagram本体は、ログインが必要なうえ利用規約で自動取得が制限されているので、直接は読みに行きません。それらの話題をまとめた公開記事やニュースを情報源にしています。

## 起動

**Windows でいちばん簡単な方法**：フォルダの中の `start-app.bat` をダブルクリックする（そのフォルダで `npm install` と `npm run phone` を実行し、アプリと管理画面のURLを表示する）。


```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY と ADMIN_TOKEN を設定
npm run dev                  # http://localhost:3000
```

- `ANTHROPIC_API_KEY` が未設定だと **デモ表示** で動きます（画面の流れだけ確認できます）
- モデルは `claude-opus-5-5`（`CLAUDE_MODEL` で変更可）。安全分類器が誤って回答を断った場合は、サーバー側で推奨モデルに自動で振り替える設定（`fallbacks: "default"`）を有効にしています
- 地図は国土地理院の淡色地図、住所→緯度経度は国土地理院の住所検索APIを使用（APIキー不要）

## データ

試作版はDBを使わず `data/db.json`（投稿・講義キャッシュ・トレンド・AIへの質問と回答・立地調査の結果）と `data/uploads/`（写真）に保存します。初回起動時に `data/seed-posts.json` のサンプル投稿が入ります。本番化の際はDBとオブジェクトストレージ、ログインに置き換えてください。
