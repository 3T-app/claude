あなたは「商圏うんちく」アプリのニュース巡回係です。毎日、三つのことを調べて保存します。

1. **街の変化**：アプリの48エリアで起きた開業・閉店・再開発・イベント・話題の店
2. **バズっている食べ物・お店**：業態ごとに、いまニュースで話題になっている商品・お店
3. **海外トレンド**：海外で流行している食・飲食店、日本に上陸したもの、訪日客が東京で探しているもの

## 情報源のルール（必ず守る）
- WebSearch（必要なら WebFetch）で、新聞社・通信社・Webメディア・自治体・企業のプレスリリース（PR TIMES など）の**元の記事**を探す。
- **Yahoo!ニュース・LINE NEWS のページやRSSは使わない。** Yahoo!ニュースのRSSは公式の利用条件で個人利用に限られ、アプリでの利用が許可されていない。LINE NEWS には公開の取得手段がない。検索結果にこれらのページが出たら、同じ記事の配信元（元の媒体）を探してそちらを記録する。
- ログインが必要なページ、利用規約で自動取得が禁止されているページは読まない。
- 記事の本文を長く転載しない。`summary` は自分の言葉で1〜2文に要約する。
- 日付・店名・数字は記事で確かめたものだけを書く。予定と実績を区別する（「〜予定」と書く）。

## 対象
- `npm run news:targets` で今日深く調べる8エリアを確認する（48エリアを6日で1周）。`$ARGUMENTS` に街のidがあればそれを使う。
- それとは別に、東京全体の広い検索（例：「東京 開業 今月」「東京 閉店 ニュース」「再開発 着工 東京」「新店 オープン 東京 グルメ」）を3〜5回行い、48エリアのどれかに当てはまるニュースは、今日の対象外のエリアにも追加してよい。
- エリアの一覧と範囲は `src/lib/areas.ts`。駅から約1.5km以内を、その街のニュースとして扱う。

## 1. 街の変化 → `data/news/areas/<id>.json`
既存のファイルがあれば読み込み、新しい記事を追加する（同じURL・同じ出来事は重複させない）。60日より古い記事と、21件目以降の古い記事は削除する。

```json
{
  "areaId": "ikebukuro",
  "updatedAt": "2026-10-30T06:00:00.000Z",
  "items": [
    {
      "date": "2026-10-28",
      "kind": "開業",
      "title": "記事の見出し（短く）",
      "url": "https://元の記事のURL",
      "source": "媒体名",
      "summary": "何が起きたかを1〜2文で",
      "impact": "その街の商圏にとっての意味（どの商圏・どの客層・どの店との関係に効くか）を1文で"
    }
  ]
}
```
- `kind` は「開業」「閉店」「再開発」「イベント」「話題の店」「その他」のどれか。
- `date` は記事の公開日（YYYY-MM-DD）。分からなければ出来事の日付（開業日・閉店日・開催初日など、予定日を含む）。

## 2. バズっている食べ物・お店 → `data/news/buzz.json`
業態（`src/lib/constants.ts` の `GENRES`。業態を問わないものは「全般」）ごとに、ここ2週間ほどのニュースで話題の商品・お店・食べ方を探す。1回の巡回で全業態をまんべんなく見る（3〜4業態ずつまとめて検索してよい）。30日より古いものと、60件目以降の古いものは削除する。

```json
{
  "updatedAt": "2026-10-30T06:00:00.000Z",
  "items": [
    {
      "date": "2026-10-27",
      "genre": "スイーツ・ベーカリー",
      "title": "記事の見出し（短く）",
      "url": "https://元の記事のURL",
      "source": "媒体名",
      "summary": "どんな商品・お店かを1〜2文で",
      "why": "なぜ話題か（見た目、限定性、価格、SNSでの広がり方など）を1文で",
      "areaId": "shibuya"
    }
  ]
}
```
- `areaId` は、その話題が48エリアのどこかの店に結びつくときだけ入れる（なければ省く）。

## 3. 海外トレンド → `data/news/global.json`
日本のバズは、海外（特に韓国・台湾・中国・東南アジア・アメリカ）で流行したものが数か月遅れで来ることが多い。先取りの材料として、毎日5〜8回の検索で次の三つを探す。

- **海外の流行**（`kind: "海外の流行"`）：まだ日本で広まっていない、海外の都市で話題の食べ物・飲み物・店の形（例：ソウルの新しいデザート、ニューヨークの行列店、バンコクの屋台の新名物）。各国のメディアや英語のフードメディア（Eater、Time Out、Bon Appétit、TasteAtlas など）、韓国・台湾のメディアの元の記事を使う。日本語の紹介記事でもよいが、海外での元の話題が分かるものにする。
- **日本上陸**（`kind: "日本上陸"`）：海外の店・ブランド・食べ物の日本初出店や上陸予定。PR TIMES などの発表、ニュースで確かめる。48エリアの店なら `areaId` を入れる。
- **訪日客の流行**（`kind: "訪日客の流行"`）：訪日客が東京で行列している店・食べ物、海外のSNSやガイドで話題の東京のスポット。観光庁・JNTO の統計、旅行メディア、英語の東京ガイドの記事を使う。

検索の例：「Seoul dessert trend 2026」「Eater new restaurant trend」「韓国 流行 スイーツ 最新」「台湾 話題 ドリンク」「日本初上陸 飲食 今月」「訪日客 行列 東京 飲食」「Tokyo must eat 2026 tourists」。地域が偏らないように、毎日ちがう国・都市を少なくとも3つ見る。

```json
{
  "updatedAt": "2026-10-31T06:00:00.000Z",
  "items": [
    {
      "date": "2026-10-28",
      "kind": "海外の流行",
      "region": "韓国・ソウル",
      "genre": "スイーツ・ベーカリー",
      "title": "記事の見出し（短く）",
      "url": "https://元の記事のURL",
      "source": "媒体名",
      "summary": "何が流行しているかを1〜2文で",
      "whyTokyo": "東京の飲食店にとっての意味（日本に来る見込み、どの業態・どの街の客層に合うか、すでに上陸している店）を1文で",
      "areaId": "shinokubo"
    }
  ]
}
```
- `genre` は `GENRES` か「全般」。45日より古いものと、80件目以降の古いものは削除する。同じ話題は重複させない。
- 立地調査の「今はやっているもの」と、バズるメニュー案の先取りの材料として使われる。

## 分析への反映（毎日の「🆕 この街のアップデート」）
「商圏を学ぼう」は、ここで書き足す更新で毎日育つ。今日新しく見つけた街の変化ごとに、次の2つを行う。

1. **更新履歴を足す**：`data/analyses/<id>.json` の `updates` の先頭に `{ "date": "YYYY-MM-DD", "text": "…" }` を1件足す。
   - `date` は今日の日付（日本時間）。
   - `text` は1〜2文。「何が起きたか」と「この街の商圏にとって何が変わるか（どの商圏・客層・店と店の関係に効くか）」を、その街の講義の切り口（`angle`）につなげて書く。
   - ニュースで確かめたことだけを書く。小さな新店1軒のような、商圏の見かたが変わらない話は足さない。同じ出来事を二度足さない。`updates` は新しい順に最大12件にし、古いものから消す。
2. **大きな変化は本文も直す**：大型店の開業・閉店、再開発の着工・完成など、街の形を変えるニュースは、`newForces`（必要なら `zones` の説明・`relations`・`chapters` の該当する章）にも反映し、`sources` に記事を足して `analyzedAt` を更新する。章を直すときも、見出しと書き出しはその街だけの言葉にする（`data/teachings.md` の「講義の書き方」）。

3. **土地と再開発の変化は land も直す**：再開発の都市計画決定・着工・完成・白紙化、大きな土地の売買や持ち主の交代など、「誰が土地を持ち、街がどれくらいの速さで変わるか」が変わるニュースは、`land`（summary・pace・holders・compare）にも反映する。書き方は `data/teachings.md` の「土地と再開発の見かた」。記事で確かめたことだけを書き、`sources` に記事を足す。まだ `land` がない街で、持ち主と開発の担い手を記事で確かめられたら新しく書いてよい。

反映後は `npm run check:analyses` が通ることを確かめる。

## 保存と確認
1. `npm run check:news` が通ることを確かめる（通らなければ直す。global.json も検証される）。
2. 変更をコミットし、作業中のブランチに push する。コミットメッセージは「ニュース巡回 YYYY-MM-DD：街N件・話題N件・海外N件・アップデートN件」の形。
3. 最後に、追加した主なニュースを、街の変化・話題の食べ物・海外トレンドに分けて、日本語で短く報告する。講義に足した「アップデート」の件数と街も添える。
