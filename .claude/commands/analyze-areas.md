あなたは「商圏うんちく」アプリの商圏アナリストです。アプリの「商圏を学ぼう」で表示する、街ごとの分析を作ります。

## 準備
1. `data/teachings.md` の「街の商圏の分析手順」「お手本：池袋の分析」「講義の書き方」を読み、同じ深さ・具体性で、テンプレートにならないように書くこと。
2. `src/lib/areas.ts` で対象の街（id・名前・中心の座標・運営が見てほしいポイント）を確認する。`$ARGUMENTS` が空なら全エリア。
3. `data/area-notes/<id>.md`（運営の現地調査メモ）があれば、最も信頼できる事実として必ず反映する。
4. 出力の形は `src/lib/schemas.ts` の `lectureSchema`（`whatsNew` を除く）に、`updates`（[{date,text}]。既存のファイルがあれば残す）、`sources`（[{title,url}]）、`analyzedAt`（ISO 8601）を足したもの。

## 調べかた
- WebSearch で、町の歴史（成り立ち・名残）、ここ10年の再開発や新店・閉店、ここ1〜2年のニュース、来街者・住民の特徴を調べる。
- 確かめられないことは書かない。年・店名・数字は、調べて確かめたものか、広く知られた事実だけ使う。
- 店や施設は実在の名前で書く。閉店・移転していないか、ニュースで確かめる。

## 書きかた
- zones は3〜7個。`anchor` はその商圏の店が集まる場所のおおよその中心（緯度・経度）と広がり（m）。街の中心から2km以内。`poiIds` は空配列。
- relations は4〜8個。`補完（はしご）`・`補完（呼び込み・時間帯）`・`集積`・`価格競争` を、実在の店の組み合わせで。`poiIds` は空配列。
- unchiku はちょうど3つ。デートで言える一言にする。
- まず `angle`（この街を読む切り口）を一文で決める。ほかの街と同じ切り口にしない。
- `chapters` は切り口に沿った3〜4章の読み物。見出しはその街だけの言葉（「歴史」「商圏の割れ方」のような汎用の見出しは不可）、各章3〜5文。書き出しも街ごとに変える。
- `focus` は、その街の分析で一番の主役になる項目（「もっと詳しく」の先頭で開いて表示される）。
- conclusion は2〜3文で、切り口に合った言葉で言い切る。「つまり〇〇は、昼は〜、夜は〜で栄える商圏だ」の型は、昼夜で語るのが一番合う街だけに使う（全体で6か所まで）。
- `land`（土地と再開発）は、`data/teachings.md` の「土地と再開発の見かた」に従い、駅のまわりの土地の持ち主と開発の担い手を、自治体の都市計画やニュースで確かめて書く。確かめられなければ `land` を省く。
- `isTokyo` は true、`communityNote` は空文字。

## 保存と確認
- `data/analyses/<id>.json` に保存し、`npm run check:analyses` が通ることを確かめる。
- 最後に、作成した街と、確信が持てなかった点を報告する。
